# 模板体系重构 P3（检测报告内联）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 长图模板下，检测报告不再是独立一屏卡片，而是把报告页图直接追加在**最后一个模块屏**的末尾，下滑即到；「检测报告」胶囊降级为滚动锚点。

**Architecture:** 纯前端两个文件。页图取数继续复用 `TraceView.vue` 已有的 `reportPagesOf` / `loadReportPages`（优先 `reportImages`，为空才把 `reportPdf` 转图，并带 Promise 级缓存），由 `TraceView` 新增一个 `reportPages`（reportId → 页图数组）解析后作为 prop 下发；`LongImageBoard` 只负责把它渲染到正确的位置。后端一行不动。

**Tech Stack:** Vue 3 `<script setup lang="ts">` + Element Plus；门禁是 `vue-tsc --noEmit`（0 错）+ 本机 vite 出包 + 浏览器实测（仓库没有 JS 测试运行器，不为此临时引入）。

**Spec:** `docs/superpowers/specs/2026-10-23-模板体系重构-design.md` §9.3、决定 9/12。

- [x] **Step 1: 加状态与解析函数**

在 `openReportDetail` 定义之前插入：

```ts
// 长图模式下要 eager 拿到报告页图（卡片屏已经没有了，页图就是正文的一部分）。
// 只在长图模式做：可视化模板走的是另一套报告区块，没必要为它把整批 PDF 都转一遍——
// 生产机 1.8G 内存、单 PDF 20MB/100 页，白加负载（同 openReportDetail 里的取舍）。
const reportPages = ref<Record<number, string[]>>({})
let reportPagesSeq = 0

async function resolveReportPages() {
  const seq = ++reportPagesSeq
  if (!isLongImageMode.value) { reportPages.value = {}; return }
  const list = testReports.value
  if (!list.length) { reportPages.value = {}; return }
  const groups = await Promise.all(list.map(async (r: any) => [r.id, await loadReportPages(r)] as const))
  // 批次切换或报告更新期间旧的一轮会晚到，不判过期就会把上一批次的页图挂到当前批次下面
  if (seq !== reportPagesSeq) return
  reportPages.value = Object.fromEntries(groups)
}

watch([isLongImageMode, testReports], () => resolveReportPages(), { immediate: true })
```

### 写代码时躲过的一个必炸的坑

`watch([isLongImageMode, testReports], …, { immediate: true })` 按"就近放在相关函数旁边"写会崩：immediate 的 watcher 在 setup 里**当场**执行回调，而 `isLongImageMode` 是在文件更后面才 `const` 声明的 computed —— 读到未初始化的绑定直接 `ReferenceError: Cannot access 'isLongImageMode' before initialization`，消费者页整页白屏。

关键是**类型检查抓不到它**：`vue-tsc` 只报同一作用域里静态可判的"used before declaration"，而这里的读取发生在 watcher 回调内，静态分析认为是延迟执行。唯一的防线是写 watcher 时确认依赖已经在上面声明过（现在代码里留了注释钉住这一点）。
