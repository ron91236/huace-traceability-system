# 侧边栏链接支持多图片与 PDF 的滚动查看 — 设计

**日期**：2026-11-03
**排期**：与《批次选择模板》一起排，本件先做（改动面小、与批次模板无文件交叠，且绿源唯品已在生产使用该功能）
**需求来源**：企业端「侧边栏链接」的跳转图片只能一张，客户要放的是检测报告（PDF，多页）和多张证书图

## 1. 目标

消费者扫码进落地页后，点侧边栏里没有跳转地址的按钮，能上下滑动翻看这个按钮挂的**多张图片或多个 PDF 的全部页**；同时删掉侧栏顶部「轻触查看」四个字。

## 2. 已确认的决策

| 决策 | 结论 | 理由 |
|---|---|---|
| PDF 什么时候转页图 | 企业保存时转并校验，消费者侧兜底现转 | 消费者打开零等待；转不动的文件不进库 |
| 查看器形态 | 单图与多图统一走一个滚动弹层 | 一条代码路径；二维码在 92vw 弹层里比 320px 更好扫 |
| 库里存什么 | 只存**原始条目**数组（图片路径 / PDF 路径） | `PdfConvertService` 已按 PDF 路径的 key 把页图缓存在 `uploads/pdf-images/<key>/`，命中缓存只是列目录，不需要再存一份页图 |
| 上限 | 单链接 ≤10 个条目；单个 PDF ≤30 页；单链接展开后 ≤60 页 | 30 沿用长图 `MAX_PAGES`；60 是防止十个三十页的 PDF 变成 300 张图的加载瀑布 |

## 3. 数据与迁移

`enterprise_side_link.image` 现在是 `VARCHAR(500)` 存单个路径，要改成存 JSON 数组：

```json
["/uploads/2026-11-03/a.png", "/uploads/2026-11-03/report.pdf"]
```

- **V29 迁移**：`ALTER TABLE enterprise_side_link MODIFY COLUMN image TEXT`。按本仓库既有迁移的写法先探 `information_schema.COLUMNS` 再决定是否执行，保证可重复运行。
- 语义与 `trace_landing_content.promoImages` 完全一致：JSON 字符串数组、`NULL` = 没配资料。
- **读侧兼容**：值不以 `[` 开头的（线上现存数据）按单元素数组处理。不加这个兼容，绿源唯品已配的那条「关注公众号」会突然变成空。
- 写侧一律归一成 JSON 数组，不留两种表示。

## 4. 后端

### 4.1 `SideLinkService.validate`

- `image` 归一成数组：不是合法 JSON 数组就拒（文案与 `LandingContentService.normalizeImageArray` 同口径），清掉空项，空数组落成 `NULL`。
- 每个元素必须以 `/uploads/` 开头。这一条不能省：这个值最终会成为消费者免登录页面上 `<img>` 的 `src`，允许外部 URL 等于把落地页变成别人的追踪像素。
- 条目数 >10 → 拒。
- 「url 与 image 至少填一项」这条老规则在数组语义下变成：**url 为空时 image 必须是至少含一项的非空数组**。原来靠空串表示"没填"，现在空数组和 `NULL` 都算没填，判定只看归一化之后的结果。
- PDF 与图片按扩展名区分，判定大小写不敏感（`.PDF` 也是 PDF）。

### 4.2 PDF 保存时校验与预热

`create` / `update` 里，对 `.pdf` 结尾的条目调用 `pdfConvertService.convertPdfToImages(url, 30)`：

- 转换抛异常 → `BusinessException`，文案带上是哪个文件，坏数据不进库。
- 展开后总页数 >60 → 拒。
- 转换的副作用（写磁盘缓存目录）不在事务回滚范围内：写库失败会留下一个用不上的缓存目录。可接受——转换按 PDF 路径的 key 幂等，下次保存会命中同一目录，不会越积越多。

### 4.3 消费者取数

`resolveForConsumer(enterpriseId)` 返回的每条链接增加瞬态字段 `pages: List<String>`（实体上 `@TableField(exist = false)`）：

- 图片条目 → 原样一条。
- PDF 条目 → 读缓存目录得到页图；缓存不在就现转一次兜底；转失败该条目跳过，不整体报错。
- `list()`（企业端编辑用）**不填 `pages`**：企业要看的是自己传的原始条目，不是系统转出来的图。

`GET /api/trace/landing/{sn}` 的 `sideLinks` 因此天然带着 `pages`，前端不需要知道 PDF 这回事。

## 5. 企业端 UI（`SideLinkList.vue`）

- 「跳转图片」改名「跳转资料」，`el-upload` 开 `multiple`、`accept="image/*,.pdf"`。
- 已选条目列成一行行：图片显示缩略图，PDF 显示文件图标 + 文件名，每条一个删除按钮。**企业端不显示页数**——`list()` 按 §4.3 不填 `pages`，要显示页数就得每次列表都去扫一遍缓存目录，不值当；企业要看内容可以直接在消费者预览里看。
- 条目顺序 = 上传顺序，本期**不做条目拖序**（链接之间的顺序已有 `sort` 接口，条目内部拖序是另一件事，需求里没提）。
- 表格「图片」列改成「资料」，显示条目数。
- 后端拒绝时提示带文件名，企业才知道是哪一个传坏了。

## 6. 消费者端 UI（`LandingView.vue`）

- 删掉 `.ld-cap`「轻触查看」整块（含样式）。可点击性仍由"进场探两次 + 按压反馈"承担。
- 点击三分支变成：有 `url` → 照旧跳转；无 `url` 但有 `pages` → 打开滚动弹层；两者都空 → 不响应。
- 弹层：`el-dialog` 宽 92vw、顶部对齐，内容区 `max-height: 82vh; overflow-y: auto`，逐页 `<img loading="lazy">`，标题用按钮文案，点遮罩关闭（沿用现有默认行为）。
- `pages` 为空数组时显示「资料暂时无法显示」，而不是一个空白弹层。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 保存时某个 PDF 转不动 | 整个保存拒绝，文案带文件名 |
| 消费者侧兜底转换也失败 | 该条 PDF 不出现，其余条目照常；全空则提示占位文案 |
| 库里是裸路径的老数据 | 读侧按单元素数组处理，表现不变 |
| 条目超 10 / 页数超 60 | 保存时明确拒绝，不静默截断 |

## 8. 测试

**后端单测**：JSON 归一化（合法数组/裸字符串/空数组/含空项）；非 `/uploads/` 前缀被拒；条目数上限；PDF 转换失败被拒且不写库；`resolveForConsumer` 把 PDF 展开成页图、图片条目原样、转换失败时跳过该条；`list()` 不填 `pages`；老数据裸路径可读。

**前端**：`vue-tsc --noEmit` + 构建。

**生产实测**（测试企业 8 + 模板 22，测完还原）：单张二维码、多张图片、单个多页 PDF、图片+PDF 混合、老数据裸路径五种；逐项确认弹层可上下滑动、逐页懒加载、遮罩可关。

## 9. 明确不做

- 不做产品级共享码（另一份设计里已确认仍用现有按码绑定）。
- 不做条目内部拖序、不做在线预览 PDF 原文（只翻页图）。
- 不动 `GET /api/trace/pdf-images` 这个免登录端点的限流缺口——它是独立议题，本设计里消费者侧的兜底转换只在企业保存时已预热的前提下才会命中，不新增暴露面。
