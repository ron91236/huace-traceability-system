# 长图溯源模板「管理端化」设计

日期：2026-10-23
状态：**已废弃（superseded）** —— 全部决定并入 `2026-10-23-模板体系重构-design.md`，请读该文件
前序设计：`2026-10-22-长图溯源模板-design.md`（本文件是对它第 4/6 节所有权模型的修订，并新增检测报告内联与权限收口）

## 1. 背景与目标

上一轮交付的长图模板把内容（模块名 + 整页图）挂在**企业**身上，由企业在企业端自助配置。
用户验收后提出两点：

1. **所有权反转到管理端**：「溯源长图」应当成为管理端「溯源模板」里的一类模板。管理端新建模板、定义模块结构，再开放给指定企业，该企业方可使用。
2. **检测报告要出现在长图流里**：位置在分屏下方，可左右滑动浏览，形态对齐参考页。

本轮调研发现一个关键事实，使第 1 点不是新增架构而是**消除一个例外**：

> 「模板自带内容」已经是本系统所有模板的既有模式。`config_json` 里直接存真实上传的图片 URL、整页背景图、地图坐标（`TemplateEditor.vue:868-875` 上传回填 `el.src`，`:906/909/915-916` 序列化）；`福鹿家`(id=14)、`鲜虾`(id=13)、`爱宠之家`(id=11) 都是管理端手工建的每客户一条模板行。企业/商品/码包只是**引用** template_key。
> `long-image` 是全系统唯一内容不挂模板的例外（`V26__trace_long_module.sql:20-23` 注释明写"只承载样式与渲染模式，不含企业内容"）。

### 参考页实测证据（`https://c.newhopedairy.cn/wp/2100826302939534326`）

| 项 | 实测结果 |
| --- | --- |
| 底部胶囊 | 4 个：`产品信息` / `有机养土` / `有机种植` / `饲养奶牛`。**没有报告胶囊** |
| 页图规格 | 一律 **1157×1637**（A4 竖版，1:√2），CDN 路径前缀 `/fsl/pdf/` → 印证是 PDF 逐页渲染 |
| 检测报告 | 「产品信息」那份 PDF 的**第 2 页**就是一张 `山东绿源唯品乳业有限公司 产品检验报告单` 整页图，人工拼在长图序列里 |
| 结论 | 参考页的"报告在下方 + 可滑动"= 报告作为页图混进长图流，**没有报告组件** |

## 2. 已确认的决定

| # | 决定点 | 结论 |
| --- | --- | --- |
| 1 | 企业端自助配置页去留 | **只收管理权**：管理端定模块名与顺序，企业端只传图 |
| 2 | 商品维度 | **去掉 goods_id**，一个模板一套图；不同商品要不同长图就建多条模板 |
| 3 | 检测报告形态 | **系统自动内联当前批次报告**到长图流末尾，同时保留胶囊与放大查看 |
| 4 | 数据模型 | **方案 A**：结构进 `config_json`，图留在 `trace_long_module`，按 `key` 关联 |
| 5 | 权限收口 | 菜单显隐 + 后端开通校验 + 企业端绑码补 `enterpriseId` 三件并入本轮 |
| ⚑ 6 | V27 是否删列 | **只加列不删列**，旧列保留但代码不再读写，下一轮再物理清理 |
| ⚑ 7 | NULL 授权语义 | **全局不动**，仅长图链路要求显式授权 |
| ⚑ 8 | 报告内联实现 | `__report` 那一屏从"卡片列表+弹窗"改为**页图直接平铺**，点击进入现有全屏查看器 |

方案 B（内容全塞 `config_json`）已排除：企业端与管理端会对同一个 `config_json` 做 read-modify-write，必然互相覆盖。

## 4. 数据模型

### 4.1 模板结构（`trace_template.config_json`）

```json
{
  "renderMode": "long-image",
  "longModules": [
    {"key": "m1764100000001", "name": "产品信息", "sortOrder": 0},
    {"key": "m1764100000002", "name": "原料麦芽", "sortOrder": 1}
  ]
}
```

- `key` 格式 `m` + 毫秒时间戳，与现有 `tpl_<System.currentTimeMillis()>`（`TraceTemplateService.java:43`）同风格。
- **`key` 一经生成不可变**。改名只动 `name`，已上传的图不会因改名而失联。
- `sortOrder` 小者在前，数组顺序即底部导航顺序。
- 管理端是 `config_json.longModules` 的唯一写入方。

### 4.2 内容表（`trace_long_module` 改造后）

```
id            BIGINT PK AUTO_INCREMENT
template_id   BIGINT      NOT NULL   -- 新增：挂模板
enterprise_id BIGINT      NOT NULL   -- 语义变更：填图的企业
module_key    VARCHAR(64) NOT NULL   -- 新增：对应 longModules[].key
pages         TEXT        NOT NULL
created_at / updated_at
UNIQUE KEY uk_tpl_ent_mod (template_id, enterprise_id, module_key)
INDEX idx_tpl_ent (template_id, enterprise_id)
```

旧列 `goods_id` / `name` / `sort_order` / `status` **保留在表里但代码不再读写**（⚑ 决定 6）。

企业未传图的模块 = 表里无该行，或 `pages='[]'`。前端 `LongImageBoard.vue` 的 `visibleModules` 已过滤 `pages` 为空的模块，胶囊不会出现——无需新增处理。

### 4.3 V27 迁移

幂等写法沿用 V26 的 `information_schema` 探测 + `PREPARE/EXECUTE`：

1. `trace_long_module` 加 `template_id`、`module_key` 两列（存在则跳过），加唯一键与索引。
2. **清空存量数据**：`TRUNCATE trace_long_module`。理由：现存 3 行是 enterprise 23 的验证数据，内容含第三方注册商标（`朝日®唯品`），无迁移价值。
3. `long-image` 模板行 **id=20 保留**，`config_json` 补成 `{"renderMode":"long-image","longModules":[]}`，由管理端后续填结构。福鹿家的 `assigned_template_ids='14,20'` 不动。
4. 同步删除 3 个侵权 webp 素材及其 `pdf-images` 派生缓存目录。

## 5. 管理端：定结构

**不扩写 `TemplateEditor.vue`**。该文件已 1389 行（`buildConfigJson:891`、`handleSave:1155`），再塞一条"长图模式"分支会让两种完全不同的编辑模型纠缠在一个组件里。

新增独立组件 `trace-frontend/src/views/admin/trace-template/LongModuleDesigner.vue`：

- 职责单一：模块清单的增 / 删 / 改名 / 拖序，产出 `longModules` 数组
- 拖序复用 sortablejs（`TemplateEditor.vue` 已在用）
- 校验：名称非空、≤50 字、删除时提示"该企业已上传的图会一并失效"
- **模块数量上限：本轮新增约束，取 10**（待确认）。理由：底部导航是 `position:fixed` 的横向滚动胶囊条，模块过多会挤占消费者视口且难以触达；参考页只有 4 个。若不需要可不设上限，但需同步给导航条加分页或折叠处理。

接入点：`TemplateList.vue` 的「新建」先选模板类型（可视化 / 长图）。选长图 → 打开 `LongModuleDesigner`，保存走既有 `POST/PUT /api/admin/trace-templates`，`config_json` 整体提交。

## 6. 企业端：只填图

`LongImageModules.vue` 改造：

- **新增**顶部模板选择器，数据源 `getAssignedTemplates()` 过滤 `renderMode === 'long-image'`
- **新增**未开通兜底：过滤后为空则整页显示"该功能尚未开通"，不再渲染任何编辑控件
- **只读**模块名与顺序（来自所选模板的 `longModules`）
- **保留**每个模块内：添加长图 / 上传 PDF 转整页 / 页图拖序 / 删除页图 / 30 页上限
- **移除**：新增模块、改模块名、模块拖序、删除模块、适用商品下拉、启用状态开关

后端 `EnterpriseLongModuleController` 接口形状：

```
GET  /api/enterprise/long-modules?templateId={id}     → 骨架 + 本企业已填 pages 的合并视图
PUT  /api/enterprise/long-modules/{templateId}/{key}  → upsert 本企业的 pages
POST /api/enterprise/long-modules/convert             → 不变
```

移除 `POST`（建模块）、`DELETE`、`PUT /sort`——结构权已归管理端。

## 7. 权限收口

### 7.1 后端新增 `assertTemplateGranted(templateId, enterpriseId)`

放在 `LongModuleService`，三个条件全过才放行：

1. 模板存在且 `status = 1`
2. `config_json.renderMode === 'long-image'`
3. **⚑ 决定 7**：`enterprise.assigned_template_ids` **显式包含**该 `templateId`。字段为 NULL/空 → **判定为未开通**（此处与 `CommonController.java:62` 的"空=全部可用"故意相反）。

`CommonController` 与 `EnterpriseController` 的通用语义**不改**，避免那 7 家 NULL 企业的其他模板一起失效。收紧只发生在长图这一条新链路上。

所有企业端长图接口（GET/PUT/convert 的调用方）都必须先过这道校验。

### 7.2 菜单显隐

`EnterpriseLayout.vue`：给 `:52` 的菜单项加 `v-if="hasLongImageTemplate"`。
`hasLongImageTemplate` 在 layout mounted 时调 `getAssignedTemplates()`，判 `some(t => t.renderMode === 'long-image')`。初值 `false`，数据回来后出现——接受一次短暂闪烁（菜单本就在进首页时才渲染）。

注意：`renderMode` 目前不在 `TraceTemplate` 实体的独立列上，而在 `config_json` 内。`/api/enterprise/assigned-templates` 返回的是实体列表，**需要让它额外暴露 `renderMode`**（解析 `config_json` 后塞进返回 Map，或给 VO 加一个派生字段），否则前端判不出来。这是本轮必须补的一处后端改动。

### 7.3 企业端绑码

`OrderCodeList.vue:69` 改为 `getTraceTemplateOptions(userStore.userInfo?.enterpriseId)`，与管理端 `OrderDetail.vue:253` 对齐。

## 8. 消费者页与检测报告内联

`TracePageService.java:240` 的 `"long-image".equals(config.get("renderMode"))` 判断**不变**——任何一条长图模板都走同一套渲染。

`resolveForTrace(enterpriseId, goodsId)` → **`resolveForTrace(templateId, enterpriseId)`**：按模板 `longModules` 的 `sortOrder` 遍历，逐 `key` 从表里取该企业 `pages`，合并成 `[{key, name, pages}]`。

**缓存版本号 `v6` → `v7`**（键形如 `tracePage::serial:00000001:b0:v6`）。结构变了，旧缓存必须整体失效；管理端保存模板时沿用 `tracePageService.evictAllCache()`。

### 8.1 报告内联（⚑ 决定 8）

"放在分屏下方"有两种读法，这里定死一种：**报告跟在最后一个模块屏的末尾，往下滑即到**，不需要先点胶囊。

现在 `__report` 那一屏渲染的是报告卡片列表 + "查看报告 ›" 点开弹窗。改为：

- 报告**不再是独立的一屏**，而是作为页图序列**自动追加在「最后一个模块」屏的下方**。消费者在当前屏往下滑，滑过模块内容就直接看到报告，与参考页"报告是那份 PDF 的第 2 页"的观感一致。
- 只追加在最后一个模块屏，**不在每个模块屏后面重复**——否则每次切模块都要再滑过一遍同样的报告。
- 「检测报告」胶囊保留在导航最末，点击语义改为"切到最后一个模块屏并滚到报告区起点"，作为快捷入口而非唯一入口。
- 报告页图来源沿用 `TraceView.vue` 既有的 `reportPagesOf` / `loadReportPages`：优先 `report_image`，为空才把 `report_pdf` 转页。
- 点任意一页 → 进入**已有的**全屏查看器（左右切多份、张内上下滚动、44×44 关闭按钮），这套在上一轮已实机验证，不重写。
- 批次切换时报告内容自动跟随（数据本就取自当前批次）。

边界：若模板只配了 1 个模块，报告就追加在那唯一一屏下方；若一个模块都没有，报告单独成屏（退化为现在的行为，保证报告始终可达）。

`LongImageBoard.vue` 改动：`REPORT_KEY` 分支从渲染卡片列表改为渲染报告页图；新增"最后一个模块屏末尾拼接报告"的渲染路径；`open-report` 事件语义改为"打开查看器并定位到该页"。

## 9. 错误处理与边界

| 场景 | 行为 |
| --- | --- |
| 企业访问未开通模板 / NULL 授权企业 | `assertTemplateGranted` 抛 `BusinessException("该模板未对您开放")` |
| 模板 `longModules` 为空 | 消费者页无长图胶囊，仅系统固定区；企业端显示"平台尚未配置模块" |
| 某模块企业未传图 | 表里无行 → `visibleModules` 过滤 → 胶囊不出现（既有行为） |
| 管理端删除一个已有企业内容的模块 | 允许；孤儿行按 `(template_id, module_key)` 保留但取数时因不在 `longModules` 内而被忽略。不做级联删除，避免误删企业素材 |
| `module_key` 在 `config_json` 里重复 | 管理端保存时校验拒绝 |
| PDF 转换失败（企业端） | 沿用现状抛 `BusinessException` |
| PDF 转换失败（消费者端） | 沿用现状返回 `[]`，前端降级 `<iframe>` |
| 单模块 > 30 页 / 名称 > 50 字 | 沿用 `MAX_PAGES` / `NAME_MAX` 校验，管理端与企业端各管一头 |

## 11. 部署与回滚

前后端**必须同批**上线（接口形状与 `config_json` 结构同时变）。

- 后端：`git push deploy master` → hook `mvn clean package -DskipTests` → 重启。构建失败自动回滚 jar 且不重启。
- 前端：服务器 1.8G 内存出不了包（vite 必被 OOM Kill），**必须本机出包 scp**，从 HEAD 的 worktree 构建，不用工作区直接 build。
- 回滚：V27 只加列不删列，旧列仍在，回滚代码即可、无需回滚 DDL。`trace_long_module` 数据回滚前备份到 `trace_long_module_bak_v27`。

## 12. 明确不做（YAGNI）

- 不做单模块「启用/停用」开关——整个模板有 `trace_template.status` 可停用
- 不做商品级长图——已决定一模板一套图
- 不做管理端传"示例图/默认图"作为企业未传图时的兜底
- 不改 `CommonController` / `EnterpriseController` 的通用"空=全部可用"语义
- 不物理删除 `trace_long_module` 的旧列（下一轮）
- 不给 `GET /api/trace/pdf-images` 加限流——上一轮遗留的独立议题，不在本轮范围
