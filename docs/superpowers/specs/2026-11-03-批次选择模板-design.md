# 批次选择模板（第四种 renderMode）— 设计

**日期**：2026-11-03
**排期**：与《侧边栏链接多资料查看》一起排，本件后做（涉及消费者主接口的缓存版本与注入顺序，风险面更大）
**需求来源**：消费者扫一个产品共用的二维码，先看基础信息，再从下拉框选该产品的历史批次，选中后展示该批次的信息

## 1. 现状：后端能力已经存在

不是从零做。仓库里已经有完整的批次切换链路：

- `GET /api/trace/{sn}/batches` → 同企业同商品的历史批次，按生产日期倒序，带 `current` 标记；仅当 `enterprise.batchSwitchEnabled=1` 才返回非空。
- `GET /api/trace/{sn}?batchId=N` → 检测报告、批次名称/生产日期/基地/检测结果、合格证整体换成该批次的数据。
- `TraceView.vue` 已有一个「选择批次」区，形态是横排胶囊 `batch-chip`，且 `showBatchPicker` 要求 `batches.length > 1`。

所以本设计的增量是：**把它做成一种可选模板、换成下拉框形态、并让"未选批次"成为一个合法的页面状态**。

## 2. 已确认的决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 「一个产品共用一个二维码」怎么落地 | 仍用现有按码绑定的普通码，只是这张码被印在整箱/展牌上共用 | 不动发放体系；批次下拉从这张码绑定的商品取历史批次 |
| 是不是第四种模板 | 是。新增 `renderMode='batch'`，权限走 `TemplateGrantGuard` | 与长图/落地页并列，管理端能选、能分配 |
| 未选批次时展示什么 | 只展示基础信息，批次区块必须选完才出现 | 与需求描述一致 |
| 正文版式 | 复用现有可视化编辑器排版 | 排版能力不丢，不用重写一套 section 渲染 |
| 只有 1 个批次 / 0 个批次 | 1 个自动选中；0 个不显示下拉，只给基础信息 | 避免"只有一个选项还要点一次" |
| 下拉里放哪些批次 | 该商品全部批次，空批次给占位 | 消费者总能找到自己要的那一批 |
| 实现路线 | 方案 A：批次交互抽 `BatchPicker.vue`，TraceView 只加判定与门禁 | TraceView 已 1000+ 行，不再往里堆状态 |

## 3. 模板与权限

- `TemplateGrantGuard` 新增 `BATCH = "batch"`，并加入 `GRANT_REQUIRED`（未显式分配 = 不开放，与长图/落地页同一套反向语义）。
- **`assigned-templates` 的"未分配=全部可用"分支必须同时滤掉 batch 模板**。这一条是踩过坑的：上次 `long-image`/`landing` 漏在 NULL 分支里，结果企业端菜单放行了入口、接口却拒绝，表现为"点了没反应"。
- 管理端「溯源模板管理」：类型选择加第四张卡「批次选择模板」；`modeToDialog('batch')` 指向**现有的 `TemplateEditor`**；「渲染方式」列加一个「批次」标签。`config_json` 就是可视化模板那套（`pages`/`sections`/`theme`）加一个 `renderMode: "batch"`，`TemplateConfigReader.validate` 不为它新增骨架校验。
- 开通判定扩成：`enterprise.batchSwitchEnabled == 1` **或** 码上的模板 `renderMode == 'batch'`。这样唯一开着旧开关的福鹿家（企业 23）行为一字不变，新企业靠分配模板开通。
- **企业端不新增任何配置页**。批次数据本来就来自企业现有的「批次管理」，这个模板只改变消费者页的行为，不引入新的企业侧内容。

## 4. 消费者页数据流

### 4.1 后端 `queryBySerialNo`

批次模板下，`batchId` 为空时**不注入批次区块**：`applyBatchBlock`、合格证 `hgz`、视频/IoT 扩展都不进结果，只留企业、商品、证书、防伪这些基础信息。

实现上有个顺序问题必须处理：现在模板解析在第 7 步（`traceTemplate`/`templateKey`），而批次块在第 5 步注入。要把模板解析提到批次注入之前，并且保留原有的 fallback（模板 key 查不到就用 `default`）。这个提前对老模板没有行为影响——老模板走的是"照旧注入码绑定的批次"。

接口返回增加一个 `batchSelectable: true`，前端据此决定渲染哪种选择器；批次列表仍由前端并行调 `/batches`，不塞进主接口（主接口是缓存的，批次列表变化不该等缓存过期）。

### 4.2 前端状态机

| 批次数 | 行为 |
|---|---|
| 0 | 不显示下拉，页面只有基础信息 |
| 1 | 自动选中该批次并拉一次带 `batchId` 的数据，下拉框显示为已选中 |
| ≥2 | 显示下拉框，未选状态 + 引导卡「请选择批次，查看该批次的检测报告与生产日期」 |

单批次自动选中意味着**两次主接口请求**：第一次不带 `batchId`（拿到基础信息和 `batchSelectable`），`/batches` 并行返回发现只有一个批次后，再带 `batchId` 拉一次。主接口是缓存的，第二次命中缓存，代价可以接受；实现时不要为了省这一趟而把批次列表塞进主接口——主接口缓存着，批次新增会延迟可见。

选中后 `GET /api/trace/{sn}?batchId=N`，批次区块整体替换；选到一个没检测报告的批次显示「该批次暂无检测报告」而不是空白。

前端判定统一读主接口返回的 `traceData.batchSelectable`，不自己解析模板配置——避免出现第二个判断口径。

### 4.3 URL

选中批次后 `router.replace('/trace/{sn}?batch=N')`。用 replace 是为了不给后退键堆历史。目的：刷新和返回不丢选择，企业可以把链接直接分享成某个批次。进页面时若 URL 带 `batch`，直接按该批次加载（等价于用户已经选过）。

### 4.4 缓存

`@Cacheable` 的 key 从 `serial:X:b{batchId}:v7` 升到 **v8**。原因：`b0` 在老模板下含义是"码绑定的批次"，在批次模板下变成"未选批次、不含批次区块"，同一 key 两种语义，灰度期会互相污染。

## 5. 组件边界

新组件 `BatchPicker.vue` 是纯展示件：

- `props = { batches: Array, modelValue: number | null, loading: boolean }`
- `emit = update:modelValue`
- 内部只有一个 `el-select`，选项文案 `批次名 · 生产日期`，无生产日期显示「生产日期待补」
- **不发请求**

数据请求与状态（`loadBatches()` / `switchBatch()` / `chosenBatchId`）留在 TraceView，它只新增：一个 `isBatchTemplate` 判定、一个"批次区块是否渲染"的门禁、以及单批次自动选中的一次副作用。

胶囊选择器 `batch-chip` 保留给"只开了企业开关、没分配批次模板"的老行为（即福鹿家），两种形态并存；以后福鹿家改分配批次模板就自然统一到下拉。

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| `/batches` 请求失败 | 下拉框不出现，页面退回只有基础信息，不给报错页 |
| 切换批次失败 | 保持上一个批次展示并提示，不清空页面（沿用现有行为） |
| `batchId` 不属于该商品 | 后端已有的「所选批次不属于该产品，请重新选择」拒绝，前端回落到未选态 |
| URL 带了非法 `batch` 值 | 当作未选处理，不报错 |
| 批次没有检测报告 | 区块渲染，内容位置显示「该批次暂无检测报告」 |

## 7. 测试

**后端单测**：权限三态（只有企业开关 / 只有批次模板 / 两者都没有）；批次模板下 `batchId=null` 不注入批次区块而老模板照旧注入；`batchSelectable` 标记；`assigned-templates` 的 NULL 分支滤掉 batch；模板解析提前后 fallback `default` 的行为不变。

**前端**：`vue-tsc --noEmit` + 构建。

**生产实测**（沿用临时绑一个未使用码、测完按存档还原的做法）：未选态只有基础信息、下拉列出全部批次、选中后批次区块出现、切到空批次给占位、单批次自动选中、刷新与后退保持所选、分享 `?batch=N` 直达、非批次模板的老页面完全不受影响。

## 8. 明确不做

- 不做产品级共享码（不新增 `/p/{企业}/{商品}` 入口，不消耗码量的诉求本期不解决）。
- 不做批次筛选口径（比如"只列有报告的批次"），已确认全部批次都列。
- 不改落地页 `/s/` 的任何行为。
- 不动 `enterprise.batchSwitchEnabled` 这个列（保留作兼容，等新模板铺开后另议退役）。
