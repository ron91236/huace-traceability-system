# 模板体系重构设计（三类模板 + 侧边栏外链）

日期：2026-10-23
状态：**已获用户批准**（2026-10-23，含全部 ⚑ 决定与第 13 条上限），可进入实现计划
**取代**：`2026-10-23-长图模板管理端化-design.md`（commit `54a0ebf`）——其全部决定并入本文第 2 节与第 6/7/8 节
前序设计：`2026-10-22-长图溯源模板-design.md`

## 1. 背景与目标

本轮把三件压在同一个子系统上的需求合成一份设计，避免 `config_json` 与 1389 行的 `TemplateEditor.vue` 被反复重构：

1. **长图模板管理端化**（已单独评审通过一轮）：内容所有权从企业反转到模板。
2. **静态落地页 + 侧边栏外链**（新需求）：模仿 `http://cti.cti-pit.com/traceIndex.html?c=13&tracecode=…`（华测另一套系统），消费者扫码先进静态落地页，右侧常驻按钮栏可跳溯源详情或外部链接（企业微博、公众号二维码等）。
3. **模板画廊扩展**：明确排除在本轮外，见第 12 节。

### 核心原则（贯穿三类模板）

> **模板 = 结构 / 骨架 / 样式 / 权限**，管理端唯一写入方。
> **企业 = 素材 / 内容 / 链接**，企业端填写。

这条原则使三类模板共用同一套权限模型、同一套编辑器骨架、同一个授权守卫。

### 写文档时相对口头呈现的一处修正

口头设计里把 `sideMenu` 放进了三模式共用的 `config_json` 顶层块。那样 `visual` 与 `long-image` 会多出"读了不用"的死配置。现改为 **`sideMenu` 只属于 `landing` 模式的 config**。外链数据本身挂企业、天然跨模式共享，将来要在详情页放开只是加一处渲染，不需要动数据结构。

### 3.2 DOM 结构

```
div#sideFloat.side-float[.expanded][.hidden]
  div.side-float-trigger          ← 悬浮态展开/收起把手（toggleExpand）
  div#btnGroup.side-btn-group[.hidden]
    button#btnTrace.side-btn      ← 「溯源详情」→ qr_url
    button.side-btn × N           ← link_list 动态生成
```

渲染条件：`hasMenuItems = qr_url || link_list.length`，两者都空则整个侧边栏不出现。

### 3.3 按钮行为三分支（"跳转链接优先"的实现）

1. `item.url` 有 → `window.location.href = item.url`
2. `item.url` 空、`item.image` 有 → 弹 `#qrcodeModal` 显示该图（公众号二维码），点遮罩关闭
3. `btnTrace` → 跳 `qr_url`；`qr_url` 为空或含 `test.com` → toast「请配置溯源详情链接」并隐藏按钮

防伪闸门：`is_fw_show_link == 1 && !fwQueryDone` → 拦截跳转 + toast。

## 5. `config_json` 骨架

```jsonc
{
  "schemaVersion": 2,
  "renderMode": "visual" | "long-image" | "landing",
  "theme": { ... },                 // 现有，不动

  // renderMode = visual（现状不变）
  "layout": "one-screen",
  "pages": [ ... ],

  // renderMode = long-image
  "longModules": [ { "key": "m<ts>", "name": "产品信息", "sortOrder": 0 } ],

  // renderMode = landing
  "landingBlocks": [ { "key": "richtext", "name": "内容", "sortOrder": 0, "enabled": true } ],
  "sideMenu": {
    "enabled": true,
    "display": "float" | "inline",   // 图1「悬浮 / 直显」
    "showTraceDetail": true,
    "showBottomEntry": true          // 对应 is_show_bottom
  },
  "gates": { "requireAntiFakeBeforeJump": false }
}
```

- `longModules[].key` / `landingBlocks[].key`：`landingBlocks` 的 key 是**固定枚举** `richtext | video | promoImages | antiFake`（骨架由模板定义哪些区块存在，key 不新生成）；`longModules[].key` 由管理端新建模块时生成 `m` + 毫秒时间戳，**一经生成不可变**，改名只动 `name`。
- `longModules` 上限 **10** 个，超出保存拒绝。

## 6. 数据表

### 6.1 `trace_long_module`（改造）

旧列 `goods_id / name / sort_order / status` **保留但代码不再读写**（决定 10）。

### 6.2 `trace_landing_content`（新增）

```
id | template_id | enterprise_id | block_key | content | created_at | updated_at
UNIQUE KEY (template_id, enterprise_id, block_key)
```
`content` 按 `block_key` 语义存不同内容：`richtext` 存 HTML，`video` 存单个 URL，`promoImages` 存 URL 的 JSON 数组。`antiFake` **只用 `enabled` 决定是否显示防伪区块，不写 `content` 行**（防伪数据由系统按码实时取，见 §12 的"全空 302"判定也要排除 `antiFake`）。

### 6.3 `enterprise_side_link`（新增，⚑ 决定 4）

```
id | enterprise_id | name | icon | url | image | sort_order | status | created_at | updated_at
INDEX (enterprise_id, status, sort_order)
```
挂企业而非模板：公众号/微博是企业固有属性，同企业多商品共用，换模板不应丢配置。保存校验：`url` 与 `image` 至少一项非空（对应"跳转链接优先"）。

## 9. 消费者端

### 9.1 新路由 `/s/:sn` → `LandingView.vue`

- 正文按 `landingBlocks` 的 `sortOrder` 渲染企业填的内容；`antiFake` 区块由系统数据渲染现有防伪结论组件
- 右侧常驻 `.side-float`：`display=float` 带把手可收起（照参考页 `expanded` 类切换），`inline` 直显
- 按钮 = 该企业 `enterprise_side_link`（`status=1`，按 `sort_order`）+（`showTraceDetail` 时）「溯源详情」→ `/trace/{sn}`
- **点击三分支，与参考页一致**：`url` 有 → 跳转；`url` 空且 `image` 有 → 弹二维码模态（点遮罩关闭）；「溯源详情」→ 跳详情
- `gates.requireAntiFakeBeforeJump` 为真且本码未做防伪验证 → toast 拦截，不给跳
- `sideMenu.showBottomEntry` 为真时，页面底部另固定一个「溯源详情」大按钮（对应图1「底部跳转」与参考页的 `window.goTraceDetail`）——参考页的侧边「溯源详情」与底部按钮是**两个入口、同一目标**，移动端拇指热区靠后者。两者都受 `requireAntiFakeBeforeJump` 闸门约束。
- 渲染条件与参考页同：无外链且 `showTraceDetail=false` 时整个侧边栏不出现（底部入口独立，不受此条件影响）

### 9.2 `/trace/:sn`

行为不变（可视化 / 长图两种渲染）。**⚑ 决定 5：本轮不加常驻侧边栏**——详情页已有底部胶囊与批次切换器，423px 宽的手机上再加右侧浮层会挤占正文视口。

非落地页模板访问 `/s/{sn}` → 302 到 `/trace/{sn}`。

### 9.3 长图页与检测报告内联（决定 9/12）

`TracePageService.java:240` 的 `renderMode` 判断不变。`resolveForTrace(enterpriseId, goodsId)` → `resolveForTrace(templateId, enterpriseId)`，按 `longModules` 的 `sortOrder` 逐 `key` 取该企业 pages 合并。缓存版本 `v6` → `v7`。

报告**不再是独立一屏**，而是页图序列自动追加在**最后一个模块屏**的末尾，往下滑即到；只追加一次，不在每个模块后重复。「检测报告」胶囊保留在导航最末，点击语义改为"切到最后一个模块屏并滚到报告区起点"。报告页图来源沿用 `TraceView.vue` 的 `reportPagesOf` / `loadReportPages`（优先 `report_image`，为空才转 `report_pdf`）；点开进入**已有**的全屏查看器（左右切多份、张内上下滚、44×44 关闭按钮），不重写。

边界：模板只配 1 个模块时报告追加在那唯一屏末尾；一个模块都没有时报告单独成屏，保证报告始终可达。

## 10. 权限收口

### 10.1 统一守卫

把上轮为长图设计的 `assertTemplateGranted` 泛化为：

```java
TemplateGrantGuard.assertGranted(templateId, enterpriseId, RenderMode required)
```

四条全过才放行：模板存在、`status=1`、`config_json.renderMode == required`、**`assigned_template_ids` 显式包含该 templateId**。字段为 NULL/空 → 判定未开通（⚑ 决定 11，与 `CommonController.java:62` 的"空=全部可用"故意相反）。

## 12. 错误处理与边界

| 场景 | 行为 |
|---|---|
| 企业访问未开通模板 / NULL 授权企业 | `TemplateGrantGuard` 抛 `BusinessException("该模板未对您开放")` |
| `longModules` 为空 | 消费者页无长图胶囊，仅系统固定区；企业端显示"平台尚未配置模块" |
| 某模块/区块企业未填 | 表里无行 → 前端过滤，胶囊或区块不出现 |
| `link_list` 的 `url` 与 `image` 都空 | 保存拒绝（"跳转链接与跳转图片至少填一项"） |
| `landingBlocks` 全部 `enabled=false` | 落地页只剩防伪区块与侧边栏；若企业内容也全空则 `/s/{sn}` 302 到 `/trace/{sn}` |
| 落地页模板被绑码但企业什么都没填 | 302 到 `/trace/{sn}`。**"全空"判定只看 `richtext/video/promoImages` 三项**——`antiFake` 不写 content 行，若把它算进去会导致"填了富文本但仍判为空"的错误 302 |
| 管理端删除已有企业内容的模块 | 允许；孤儿行保留但取数时因不在 `longModules` 内被忽略，不做级联删除以免误删企业素材 |
| `module_key` 在 `config_json` 重复 | 管理端保存拒绝 |
| `longModules` 超 10 个 | 管理端保存拒绝 |
| PDF 转换失败（企业端） | 抛 `BusinessException`（现状） |
| PDF 转换失败（消费者端） | 返回 `[]`，前端降级 `<iframe>`（现状） |
| `requireAntiFakeBeforeJump=true` 且未验证 | toast「请先完成防伪查询」，阻断跳转 |

## 14. 分阶段实施顺序

一份 spec，四阶段，每阶段可独立上线：

1. **P1 地基**：`TemplateGrantGuard` + `assigned-templates` 暴露 `renderMode` + 菜单显隐 + 绑码补参数 + V27 建表加列。风险最低，先修权限漏洞。
2. **P2 长图管理端化**：`LongModuleDesigner` + 企业端改造 + `resolveForTrace` 换键 + 缓存 v7 + 清空侵权数据。
3. **P3 报告内联**：`LongImageBoard` 的 `REPORT_KEY` 屏改页图平铺 + 追加到最后一个模块屏。
4. **P4 落地页**：`LandingBlockDesigner` + `LandingContent`/`SideLinkList` 企业页 + `/s/:sn` 路由与 `LandingView` + 公开接口。

依赖关系：**P1 是一切的前提**（守卫与建表）。P2 → P3 串行，因为两者都动 `LongImageBoard` 与 `resolveForTrace` 的输出形状，先定新形状再改渲染，避免同一处改两遍。P4 只依赖 P1，可与 P2/P3 并行开发但建议最后上线（改动面最大、含新公开路由与接口）。
