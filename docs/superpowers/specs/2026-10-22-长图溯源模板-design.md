# 长图溯源模板（企业自定义模块自由拼接）设计

日期：2026-10-22
状态：已与用户逐节确认，待复核

## 1. 背景与目标

参考页面：新希望乳业「朝日唯品」溯源页 `https://c.newhopedairy.cn/wp/2100826302939534326`。
实测其结构为：每屏内容是 PDF 逐页渲染出的整页 PNG（1157×1637）纵向无缝拼接；底部一排胶囊导航（产品信息 / 有机养土 / 有机种植 / 饲养奶牛）；点击胶囊是**整屏替换**内容区，不是锚点滚动。

目标：在现有溯源系统中新增一套同风格的「长图溯源模板」，要求

1. 展示内容可长图自由拼接；
2. 检测报告点击放大后，左右滑切换上一份/下一份，单页超高时张内上下滚动；
3. 底部模块可由企业自由增加、命名、排序。

## 2. 已确认的需求决定

| 决策点 | 结论 |
| --- | --- |
| 长图素材来源 | 企业上传 PDF 或竖版长图，系统统一转成整页图后拼接 |
| 谁来配置 | 企业端自助配置，平台按企业开通该模板作为权限管控 |
| 系统数据区块 | 防伪结论条、批次切换、合格证保持固定；检测报告作为系统固定模块进入底部导航，内容取自当前批次 |
| 放大查看交互 | 左右切报告 + 张内上下滚动 |
| 架构方案 | 方案 A：独立模块表 + 模板渲染模式 |
| 模块归属 | 企业默认 + 商品级覆盖 |

## 3. 复用的既有能力

- `PdfConvertService.convertPdfToImages(url)`（trace-backend/src/main/java/com/huace/trace/service/PdfConvertService.java:52）：PDFBox 按 130DPI 逐页渲染 JPEG，按文件内容哈希缓存到 `uploads/pdf-images/<hash>/`，命中缓存直接返回 URL 列表。长图拼接的转图链路直接复用，不引入新依赖。
- 模板分配链路：`enterprise.assigned_template_ids`（sql/V12__enterprise_assigned_templates.sql）+ `GET /api/common/trace-templates?enterpriseId`（CommonController.java:57）。企业能否选用某模板已由它管控，本次不新增权限字段。
- 上传与压缩：`POST /api/upload`（TracePageController.java:115）落本地磁盘并写 `sys_file`；前端 `compressImage`（trace-frontend/src/api/common.ts:4-55）宽度 ≤1080、长图保留完整高度。
- 拖拽排序：sortablejs 已在依赖中，模板编辑器已在用（TemplateEditor.vue:478,782）。
- 图片查看器：Element Plus `el-image-viewer`（配合 `el-image` 的 `preview-src-list`），已有可见关闭按钮与画布样式覆盖（TraceView.vue:1834-1847）。

## 4. 数据模型

### 4.1 模板行（样式开关）

`trace_template` 新增一行，仅承载样式与渲染模式，不含企业内容：

- `template_key = 'long-image'`
- `template_name = '长图溯源'`
- `config_json = {"renderMode":"long-image"}`
- `status = 1`

消费者页面的模板仍由 `code_package_item.trace_template`（存 templateKey）决定，与现有链路一致。

### 4.2 模块表

```
trace_long_module
  id            BIGINT PK AUTO_INCREMENT
  enterprise_id BIGINT      NOT NULL            -- 归属企业
  goods_id      BIGINT      NULL                -- NULL=企业默认，非空=商品专属
  name          VARCHAR(50) NOT NULL            -- 企业自由命名，即底部胶囊文案
  pages         JSON        NOT NULL            -- 整页图片 URL 数组，顺序即拼接顺序
  sort_order    INT         NOT NULL DEFAULT 0  -- 导航顺序
  status        TINYINT     NOT NULL DEFAULT 1  -- 1启用 0停用
  created_at / updated_at
  KEY idx_ent_goods (enterprise_id, goods_id, status, sort_order)
```

迁移脚本 `sql/V26__trace_long_module.sql`，按仓库既有写法用 `information_schema` 判重实现幂等（参照 sql/V25__enterprise_batch_switch_flag.sql）。

### 4.3 归属优先级

取模块时：该商品存在任一 `status=1` 的商品级模块 → 只用商品级模块；否则整体回落企业默认模块。不做两批混排。码未绑定商品（`goods_id` 为空）时直接走企业默认。消费端再过滤 `pages` 为空的模块。

## 5. 后端

### 5.1 企业端接口（新增）

挂在企业端控制器下，风格与 `EnterpriseController` 一致：

- `GET  /api/enterprise/long-modules` 列表（含商品归属）
- `POST /api/enterprise/long-modules` 新建
- `PUT  /api/enterprise/long-modules/{id}` 改名/换图/改商品归属/启停
- `DELETE /api/enterprise/long-modules/{id}` 删除
- `PUT  /api/enterprise/long-modules/sort` 拖拽排序（body 传 id 数组）
- `POST /api/enterprise/long-modules/convert` 上传后的 PDF 转图，返回页图 URL 数组

约束：

- 所有写操作的企业 ID 一律取登录态，忽略请求体传入的 `enterpriseId`，杜绝跨企业写入。
- 单 PDF ≤20MB、≤30 页，超限抛 `BusinessException`（服务器 1.8G 内存 / 1G 堆，不能一次渲染上百页）。
- 转换成功才写 `pages`，失败不落半截数据。
- 删除模块只删记录，不删图片文件（转图结果按内容哈希共享）。
- 任何增删改排序后调用 `tracePageService.evictAllCache()`。

### 5.2 消费端读路径

`TracePageService.queryBySerialNo` 在解析出 `templateConfig.renderMode == "long-image"` 时才多查一次模块，结果新增 `longModules` 字段（`[{key,name,pages[]}]`，`key` 即模块 ID 字符串，前端用它做导航选中态），随主接口一次返回，避免前端二次请求闪烁。缓存 key 版本由 `:v5` 升为 `:v6`（TracePageService.java:66）。

检测报告数据仍走现有 `batch` + `testReports` 块，长图模板不复制一份。

## 6. 前端

### 6.1 企业端配置页

新增 `trace-frontend/src/views/enterprise/long-image/LongImageModules.vue`：

- 左栏模块列表：sortablejs 拖拽排序、内联改名、新增、删除、启用/停用；每项显示归属（全部商品 / 指定商品）。
- 右栏当前模块页图：拖拽调序、删除、追加上传；PDF 上传后调 convert 接口，返回的页图即时追加并预览确认再保存。
- 商品归属下拉取本企业商品。
- 路由 `enterprise/long-image`（router/index.ts 企业端路由表末尾），菜单项加在 `components/EnterpriseLayout.vue` 合格证管理之后。
- 若 `/api/common/trace-templates?enterpriseId` 未返回 `long-image`，页面置灰并提示「请联系平台开通长图模板」。

### 6.2 消费端渲染

`TraceView.vue`（1850 行）继续作为数据所有者，新增 `renderMode === 'long-image'` 分支，页面主体交给新的纯展示组件 `components/trace/LongImageBoard.vue`（props：模块列表、报告、合格证、当前模块 key；emit：打开报告），避免 TraceView 继续膨胀。

页面结构：

- 顶部固定：防伪结论条 `truth-bar` + 批次切换器 `batch-picker`（沿用现状）。
- 中部内容区：当前模块，切模块=整屏替换并回到顶部。
- 底部固定胶囊导航：企业模块（按 `sort_order`）+ 系统固定「检测报告」+ 有证时「合格证」。
- 长图渲染：`width:100%; display:block` 无缝顺排，`loading="lazy"` 懒加载，首屏只加载前两页。

### 6.3 检测报告查看器

把当前批次所有报告的页图拉平成一条有序序列并记录归属索引：`el-image-viewer` 左右滑即上一份/下一份；单页超高时允许纵向滚动（覆盖 `el-image-viewer__canvas` 溢出与图片定位），保留现有可见关闭按钮。老模板的报告弹窗行为不变。

## 7. 边界与错误处理

- 加密/损坏 PDF：转换接口返回明确业务异常文案，前端 toast，模块保持原状。
- 空模块（无 `pages`）：保存时拒绝；消费端二次过滤，导航不出现空胶囊。
- 商品级模块全部停用：按 4.3 回落企业默认，避免页面空白。
- 历史脏数据 `renderMode` 缺失或模板被删：走现有默认模板兜底，不白屏。
- 老模板零影响：所有新逻辑都在 `renderMode` 分支内。

## 8. 测试与验收

后端单测（在服务器 JDK 17 上跑，本机只有 JDK 8）：

1. 归属优先级三种情形（商品级命中 / 回落企业默认 / 商品级全停用回落）；
2. 非长图模板不触发模块查询；
3. PDF 页数与体积上限拒绝；
4. 跨企业写入被拒（请求体伪造 enterpriseId）；
5. 模块变更后缓存被清空。

其他验证：

- `V26` 迁移脚本连跑两次幂等无报错。
- 前端 `vue-tsc` 类型检查 + 本机 Vite 出包（服务器内存不足，前端必须本机构建后 scp 上传 dist）。
- 端到端浏览器流程：企业端建 2 个模块 → 上传 PDF 转图 → 改名拖序 → 管理端把 `long-image` 分配给企业 → 订单条码绑定该模板到一个码 → 手机尺寸打开 `/trace/{serialNo}` 验证整屏替换、底部导航、报告左右切份 + 张内上下滚 → 用未开通企业确认老模板无回归。
- 生产验证一律使用可回滚的测试数据，验证后清理。

## 9. 非目标（本次不做）

- 不做长图的在线编辑/裁剪/加文字水印，图由企业提供。
- 不做模块级权限（谁能改）之外的第二层审批流。
- 不做 PDF 转图的异步任务队列与进度条，同步转换 + 页数上限足够。
- 不改数字标签（dl）子系统。
