# 农产品承诺达标合格证预研报告

> 预研日期：2026-09-02
> 范围：政策与市面模式调研、与溯源系统融合方案（溯源+合格证链接展示、合格证单独链接展示）、实体标签打印方案

---

## 一、政策背景（结论先行）

《农产品质量安全承诺达标合格证管理办法》由农业农村部以 **2025 年第 4 号部令**发布，**自 2026 年 2 月 1 日起施行**；2026 年 5 月 1 日起全国全面启用统一新样式（此前开具的旧证在有效期内仍可流通）。

**合格证必须载明的要素（法定清单）：**

| 要素 | 说明 |
|---|---|
| 承诺事项 | 如"不使用禁用农药兽药、不非法添加"等承诺条款，需勾选/列明 |
| 承诺依据 | 如"自我承诺""委托检测""合格证""质量安全控制"等，可附检测报告 |
| 产品名称 | 农产品名称 |
| 数量（重量） | 本批次数量或重量 |
| 产地 | 产地（省/市/县，可到基地） |
| 承诺主体 | 开具单位（生产者/收购者名称） |
| 联系方式 | 联系电话 |
| 开具日期 | 承诺日期 |
| 二维码 | 政策鼓励使用二维码；扫码优先展示核心信息，**可整合追溯标签与质量标志** |

要点：合格证由**生产经营者自行开具**（不是政府颁发），可采用信息化、印刷或手工形式；电子证与纸质证等效。政策明确鼓励"合格证+追溯码"一体化，这正好是本溯源系统的切入点。

## 二、市面应用模式调研

### 2.1 参考样例实测：华测平台 `hgz.html?c=509`

对用户提供的示例链接做了实测拆解（页面可访问，数据接口为 `GET http://www.cti-pit.com/sy/search/qualified?id={证号}`），其架构如下：

- **静态 HTML + Ajax 取数**：`hgz.html` 是纯静态页，通过 `?c=证号` 参数调用 JSON 接口渲染，页面与数据分离，链接稳定（换样式不用改链接）；
- **页面结构**：顶部导航分节（产品信息 / 主体信息 / 检测信息 / 承诺达标合格证），无数据的板块自动隐藏；
- **合格证卡片字段**（与本系统映射关系见 3.1）：
  - 承诺语按主体类型区分："我承诺**生产销售**的食用农产品" / "我承诺**销售**的食用农产品"（生产者 vs 收购者）；
  - 承诺事项列表（多选勾选展示）、承诺依据列表（复选框样式，可挂"查看检测报告"）；
  - 详情行：产品名称、重量或数量、产地、承诺主体、联系方式、开具日期、主体签名/盖章图；
  - 卡片下方有**查询网址（溯源链接 queryUrl）与查询电话**，即"合格证页回链溯源页"；
- **打印**：接口层预留了 Hiprint 打印设计（`/sy/hiprint/my_print` 等），Hiprint 是国内 Web 端标签/票据打印的主流开源方案；
- **检测信息**：挂载快检/自检记录（日期、方法、内容、结果、机构、报告图片）。

### 2.2 市面三种典型模式

1. **政府/平台统一开证模式**：各省农业农村部门追溯平台（如国家农产品质量安全追溯平台、省级"浙农码"类平台）统一开证、统一赋码，企业登录平台打印。特点是样式全省/全国统一，但企业数据要重复录入，且平台归政府管，商业系统只能做对接。
2. **企业自建/活码模式**：用草料二维码等活码平台套用"农产品承诺达标合格证"模板（草料官方即有合格证标签模板与打印机选型教程），二维码指向自建页面或平台页，配热敏标签打印机（精臣/得力/芯烨等）批量打印不干胶标签。特点是上手快，但数据与溯源系统割裂、样式合规性靠模板方保障。
3. **华测式整合模式（参考样例）**：合格证作为溯源体系的一个环节，合格证页 ↔ 溯源页互链，检测报告挂载，电子证+打印一体化。**与本系统现状最接近，融合成本最低**。

### 2.3 实体标签样式与打印方案（市面现状）

- **样式**：新样式为统一版式，含证头"承诺达标合格证"、承诺事项、承诺依据（勾选框）、产品名称/数量/产地/承诺主体/联系方式/开具日期、签名盖章区、二维码区；
- **常见规格**：A5 纸（148×210mm，可一版两联/四联裁切）、A4 六联；热敏不干胶标签 100×70mm、80×60mm；便携标签机 50×30mm（小票式，适合商超肉菜）；
- **打印硬件**：批量开证多用 4 寸热敏标签打印机（203dpi 即可，二维码清晰），少量用 A4/A5 激光打印。标签纸选三防热敏（防水防油防撕）为市面主流；
- **软件对接**：Web 端打印三种主流做法——① 浏览器打印样式（print CSS，零依赖）；② Hiprint 可视化模板设计（参考样例在用）；③ 服务端生成 PDF/图片再打印（适配嵌入式小票机）。

## 三、与本系统融合方案设计

### 3.1 数据模型（新增 `hgz` 表，字段对齐法定要素）

```
hgz（承诺达标合格证）
├─ id, code            -- 证号（如 HGZ20260902-XXXX，或复用批次号段）
├─ enterprise_id       -- 承诺主体（关联 enterprise）
├─ batch_id            -- 关联批次（可选，与溯源打通的关键）
├─ goods_id            -- 关联商品（可选）
├─ user_type           -- 1 生产者 / 2 收购者（决定承诺语表述）
├─ product_name        -- 产品名称
├─ number              -- 数量（重量）
├─ place_of_origin     -- 产地
├─ promise_user        -- 承诺主体名称（冗余存储，防企业改名影响历史证）
├─ contact             -- 联系方式
├─ use_time            -- 开具日期
├─ signature           -- 签名/盖章图片（复用 /api/upload 本地磁盘存储）
├─ promise_list        -- JSON：承诺事项 [{title, is_select}]
├─ basis_list          -- JSON：承诺依据 [{title, is_select, image(检测报告)}]
├─ is_show_enterprise  -- 是否展示企业信息
├─ status              -- 有效/作废
└─ qr_url / query_url  -- 合格证单独链接与溯源回链地址（生成后固化）
```

复用既有能力：`QrCodeUtil`（zxing 二维码生成）、`/api/upload` 文件上传、Poster 模块的 slug 路由与 Nginx 配置模式、`enterprise/batch/goods/enterprise_base` 现有数据（自动填充产品名/产地/主体/联系方式）。

### 3.2 需求一：溯源信息 + 承诺达标合格证链接展示

**目标**：扫溯源码的用户能看到合格证，扫合格证的用户能回到溯源信息，双向闭环。

- **溯源页侧**（`/trace/{serialNo}`，即 TraceView）：
  - 后端 `TracePageService` 返回结构新增 `hgz` 区块：按批次/商品反查最新有效合格证（含证号、产品名、承诺事项摘要、单独链接）；
  - 前端在溯源页加"承诺达标合格证"卡片区（有证才展示），含"查看合格证"按钮 → 跳转合格证单独链接；无证不显示；
- **合格证页侧**：页面上提供"溯源查询"入口（参考样例的 `queryUrl` 字段）：有绑定批次/溯源码时显示按钮直达溯源页；未绑定时只展示合格证本身；
- **二维码策略**：溯源码二维码内容仍是溯源页链接；溯源页内合格证卡片再放合格证二维码/链接，避免一码双义。

### 3.3 需求二：承诺达标合格证单独链接展示

**目标**：每张合格证有独立稳定链接 + 独立二维码，可单独印刷在实体标签上。

- **路由方案**：复用 Poster 的 Nginx 路由模式，新增公开路由 `/hgz/{code}`（或按用户示例习惯支持 `/hgz.html?c={code}`，两者等价，后端重写即可）。Nginx 在现有 `/poster/` 同级加一条 `/hgz` 代理规则；
- **页面实现**（参考样例，两个选项）：
  - **方案 A（推荐）**：静态 HTML 页 + Ajax 取数——`hgz.html` 放前端 dist，通过 `?c=证号` 调 `GET /api/hgz/{code}` 公开接口渲染。优点：页面与数据分离、链接极稳、样式升级不影响链接、与参考样例架构一致；接口需白名单放行（SecurityConfig 公开路径）；
  - **方案 B**：后端模板渲染服务端直出 HTML。优点：SEO/爬虫友好；缺点：改样式要动后端。当前需求不需要 SEO，选 A；
- **公开接口** `GET /api/hgz/{code}`：返回合格证全字段 + 企业主体信息（可选，受 is_show_enterprise 控制）+ 检测依据图片地址。数据不敏感可加 5 分钟 Redis 缓存（复用 tracePage 缓存模式，注意白名单类型约束——见项目记忆）；
- **二维码**：开证时用 QrCodeUtil 生成 `https://trace.cti-pit.com/hgz/{code}` 的二维码，供打印与溯源页引用。

### 3.4 企业端开证流程（新增"合格证管理"菜单）

```
企业端 → 合格证管理 → [新建合格证]
  1. 选择批次（或直接选择商品+基地）→ 自动带出 产品名称/数量/产地/主体/联系方式
  2. 勾选承诺事项（默认勾选合规条款）、承诺依据（可上传检测报告图）
  3. 确认承诺语类型（生产者/收购者）、签名盖章图上传
  4. 保存 → 生成证号 + 单独链接 + 二维码
  5. 列表页操作：查看/打印/作废（作废后公开页显示"该合格证已作废"）
```
管理端（AdminController）增加合格证列表查询与作废能力，便于监管排查。

### 3.5 实体标签打印方案（三步走）

- **第一步（起步，零依赖）**：企业端"打印合格证"按钮打开打印专用视图（独立路由 `/enterprise/hgz/{id}/print`），用 **print CSS** 按统一新样式排版（A5 或 100×70mm 不干胶），浏览器 Ctrl+P 打印。可先支持 A5 与 4 寸热敏两种尺寸预设；
- **第二步（模板化）**：引入 **Hiprint**（参考样例同款，Vue 生态成熟）：企业可自定义标签模板（字号、字段位置、logo），模板存企业配置；打印走浏览器打印协议，适配主流热敏/激光打印机；
- **第三步（如需要）**：服务端生成打印 PDF/PNG（如 iText/Thumbnailator），适配无浏览器的嵌入式小票机、微信小程序云打印场景；
- **硬件建议**：批量开证推荐 4 寸热敏标签打印机（203dpi，市价 300–600 元档，如精臣/得力/芯烨）；少量场景用 A5 激光打印即可。标签纸选三防热敏。

### 3.6 与政策衔接注意点

- 承诺事项文案必须包含法定要素表述，**默认文案需企业逐项确认**，平台只做载体不做替诺（页面底部建议加"本证由生产经营者自行开具，对其真实性负责"脚注，参考样例已有类似表述）；
- 2026-05-01 后新开证一律按新样式排版（打印模板内置新样式字段）；
- 合格证与检测报告挂钩时，报告图仅作依据展示，不替代官方检测机构报告；
- 若未来需要对接政府追溯平台（数据互通），预留 `hgz` 表导出/上报字段即可，本方案不依赖政府平台。
